# Rule: Plan-Before-Execute (ต้องวางแผนและขออนุมัติก่อนลงมือทำเสมอ)

## 🎯 Core Directive
**ห้ามเริ่มทำการแก้ไขโค้ด, รันคำสั่งที่เปลี่ยนแปลงไฟล์, หรือสร้างไฟล์ใหม่ในทันทีเมื่อได้รับคำสั่งจากผู้ใช้** 
ต้องปฏิบัติตามกระบวนการ **Plan -> Confirm -> Execute** อย่างเคร่งครัด 100% เสมอ

---

## 📋 ขั้นตอนการทำงานที่ต้องปฏิบัติทุกครั้ง (Strict Protocol)

### 1. 🔍 วิเคราะห์ & นำเสนอแผนการดำเนินงาน (Action Plan)
เมื่อได้รับคำสั่ง, ความต้องการใหม่, การปรับปรุง UI, หรือแจ้งบั๊ก ให้สรุปและตอบกลับผู้ใช้ด้วยโครงสร้างดังนี้:
- **🎯 เป้าหมาย (Goal):** สรุปสิ่งที่เข้าใจจากคำสั่งของผู้ใช้ให้ตรงกัน
- **📁 ไฟล์ที่เกี่ยวข้อง (Target Files):** ระบุชื่อไฟล์และตำแหน่งพาธที่จะสร้างหรือแก้ไข
- **🛠️ ขั้นตอนการลงมือทำ (Step-by-Step Plan):** ลิสต์รายละเอียดทีละขั้นตอนอย่างชัดเจน
- **⚠️ ผลกระทบ & จุดที่ต้องระวัง (Impact & Considerations):** เช่น ความปลอดภัยของข้อมูล, ความเข้ากันได้กับฐานข้อมูล, หรือผลต่อหน้า UI อื่นๆ

### 2. ⏳ หยุดรอการยืนยันจากผู้ใช้ (Wait for User Approval)
- หลังจากนำเสนอ Action Plan เสร็จสิ้น **ให้หยุดและถามความเห็นของผู้ใช้**
- **ห้ามเรียกใช้ Tool แก้ไขไฟล์ (เช่น `replace_file_content`, `write_to_file`, `run_command` ที่กระทบโค้ด) ในรอบเดียวกันกับการเสนอแผนเด็ดขาด**
- รอจนกว่าผู้ใช้จะส่งข้อความอนุมัติ เช่น *"ตกลง", "จัดไป", "ลุยเลย", "โอเค", "ทำได้เลย"* หรือระบุให้ปรับปรุงแผน

### 3. 🚀 ลงมือปฏิบัติงาน (Execute after Approval)
- เมื่อได้รับการอนุมัติแล้ว จึงเริ่มแก้ไขไฟล์ตามแผนที่วางไว้
- บันทึกความคืบหน้าลงใน `CURRENT_TASK.md` ทุกครั้ง
- รันการตรวจสอบความถูกต้อง (เช่น `npx tsc --noEmit`) หลังทำเสร็จ

---

### ⚠️ ข้อยกเว้นเพียงกรณีเดียว
หากผู้ใช้ระบุในข้อความอย่างชัดเจนตั้งแต่แรก เช่น *"ทำ...แล้วลงมือทำได้เลยไม่ต้องรอถาม"* หรือ *"อนุมัติให้ทำตามแผนได้ทันที"* AI จึงจะสามารถสรุปแผนสั้นๆ พร้อมดำเนินการได้ในคราวเดียว
